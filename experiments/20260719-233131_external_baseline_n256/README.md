# Experiment: External Baselines at N=256

## Purpose

Compare PuerCGP with the supported iBFS, Glign, ForkGraph, and Gunrock
implementations under one graph/query manifest and one timing protocol.

## Hypothesis

PuerCGP should improve total query throughput by sharing topology access in
push and coalescing query-state access in pull. Online scheduling is expected
to help only when its planning cost and delayed starts are offset by additional
sharing.

## Dataset

- `cit-Patents`
- `soc-orkut`
- `soc-twitter`
- `soc-sinaweibo`
- GR and CSR graphs use deterministic symmetric integer weights in `[1,64]`
  generated with seed `20260719`.

## Scenario

- BFS/SSSP/SSWP: `N=256`, `Q=64`.
- PageRank/PPR: `N=256`, `Q=32`, 10 iterations where the artifact exposes a
  semantically equivalent fixed-iteration mode.
- PuerCGP frontier variants: all-push + online runner, hybrid + online runner,
  and all-pull without online scheduling.
- Default protocol: 2 warmups and 5 measured repeats; report the median.
- ForkGraph overrides made to shorten the remaining run: Twitter BFS uses
  1 warmup plus 1 measured run; Twitter SSSP and SinaWeibo BFS/SSSP use
  0 warmups plus 1 measured cold run. These cases are marked in all outputs.
- Homogeneous batches only.

## Environment

- GPU: NVIDIA Tesla V100-SXM2-32GB.
- CPU: 2 x Intel Xeon Platinum 8260, 48 physical cores, 96 hardware threads.
- OS: Debian Linux 6.1.
- Runtime and exact build metadata are captured under `artifacts/environment/`.

## Command

Commands are generated by `scripts/run_external_baselines.py`. Aggregated
results are in `result.csv`; per-run status, stdout, stderr, and metadata are
under `artifacts/`.

## Results

The planned matrix is complete with recorded failures: 97 cases completed and
6 failed. See `RESULTS.md` for the primary latency/throughput tables and
`result.csv` for machine-readable results.

Across comparable cases, best-Puer geometric-mean speedups are 68.30x over
Glign (11 cases), 139.99x over ForkGraph (7 cases), and 9.52x over sequential
Gunrock (8 cases). Specialized iBFS remains faster on aggregate BFS: the
best-Puer/iBFS geometric-mean speedup is 0.694x.

## Observations

- Existing weighted GR files passed full deterministic-weight validation on
  all four datasets before measurement.
- Native ForkGraph PPR and Gunrock PPR are residual/PR-Nibble algorithms,
  whereas PuerCGP currently implements dense power iteration. Their semantic
  comparability is audited before inclusion in the main table.
- Weighted BFS/SSSP/SSWP checks completed with 20 matching signatures and no
  correctness failures.
- Strict-Q Gunrock BFS streams64 runs OOM on Orkut, Twitter, and SinaWeibo.
- Glign SinaWeibo SSWP and ForkGraph SinaWeibo SSSP were killed by SIGKILL;
  the latter reached at least 131 GB observed RSS and is classified as a
  probable host OOM.
- ForkGraph corrected runs use 48 bound physical cores and LLC-sized range
  partitions. The original P=8/OMP=96 diagnostic runs are excluded.

## Conclusion

PuerCGP substantially outperforms the general CPU/GPU context baselines on
most supported algorithms, while iBFS demonstrates that a specialized GPU BFS
implementation remains a strong baseline. The result set is suitable for
design iteration, but mixed ForkGraph sampling and shared-host CPU contention
make those CPU numbers preliminary rather than publication-ready.

## Issues

- ForkGraph was measured on a shared CPU host; rerun on an exclusive node for
  publication.
- ForkGraph Twitter SSSP and SinaWeibo cases use single cold measurements by
  request and therefore have no variance estimate.
- Unsupported or semantically different algorithm pairs are excluded rather
  than assigned artificial results.

## Next Steps

For publication, rerun the marked ForkGraph cases with the default 2+5
protocol on an exclusive node and retain strict Q=64 OOM outcomes.
